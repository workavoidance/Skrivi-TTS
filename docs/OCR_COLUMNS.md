# Two-column OCR experiment

19 September 2026. Test only: installed 0.3.0, OCR runtime and model files unchanged.
User reports 0.3.0 works perfectly on another machine and asked what handles columns easily.

Used the existing Tesseract 5.5.2 / nor+eng weights. Compared built-in page segmentation
3 (automatic page), 4 (single column), 6 (current single block), 11 (sparse text).
Documentation: https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html#page-segmentation-method
No additional model, dependency, download or licence change is needed to choose a mode.

## Fixtures and scoring

30 synthetic two-column images: English/Bokmal/Nynorsk, Arial/Times 28px, five layouts
(plain, spanning heading, narrow gutter, staggered baselines, left-aligned page footer).
24 existing single-column controls. All image text is synthetic. Output compared with
known left-column-then-right-column reference after whitespace normalisation. Title
is expected first and page footer last. Ten distinct body-line anchors separately
check main-column ordering; that metric does NOT include title/footer correctness.
Two runs per fixture/mode, clearing adaptive state, production-style 16px white border.
Images under ignored build/ocr-columns; repeatable runner tests/ocr_columns.py using
build/ocr-env. Existing controls can be regenerated by tests/ocr_screening.py.
A heading-width assertion ensures the tested title actually spans the gutter.

## Results

| Mode | Exact two-column output | Body anchors in correct order | Exact single-column controls | Median two-column recognition |
| --- | --- | --- | --- | --- |
| Automatic page (3) | 21/30 | 27/30 | 22/24 | 0.149 s |
| Single column (4) | 5/30 | 5/30 | 22/24 | 0.150 s |
| Current single block (6) | 0/30 | 0/30 | 22/24 | 0.147 s |
| Sparse text (11) | 0/30 | 0/30 | 22/24 | 0.148 s |

Automatic page was exact on all 18 plain/narrow/staggered examples. It was exact on
3/6 spanning-heading examples; all three Times examples incorrectly interleaved
columns despite recognising the words. In all six footer examples the main columns
were ordered, but the left-aligned footer was read between them rather than last.
A footer's semantics are not unambiguously recoverable from placement alone.

Both automatic page and current mode reproduced 22/24 single-column controls
exactly; auto took 0.060 s median versus 0.055 s for current mode. Timings exclude
worker startup, screenshot selection and speech. Raw evidence: OCR_COLUMNS.json.

## Decision

The easy improvement is an optional Automatic page layout setting (PSM 3). It works
well for the clean two-column body in this small screen. Recommend selecting the
body without shared headings or footers. Retain the existing single-block fallback;
do not claim automatic mode reliably understands every page or make it a silent
universal replacement based on this test. Sparse-text mode is not a reading-order fix.

No new release or application change made from this experiment. Implementing a mode
choice next would require a new immutable OCR runtime profile, since the current
worker freezes its segmentation setting. Existing language weights remain reusable.
